# OneOps — Phone-First Incident Engineering Prototype

**Reproduce Before You Remediate.**

This repository is the first real implementation slice of the finalized OneOps architecture. It is intentionally not a fake clickable demo. The mobile app talks to a working backend state machine, captures real camera evidence, starts real voice input, and controls a deterministic incident workflow. The lab contains a real containerized Blue/Green service pair, Prometheus metrics, a gateway with endpoint-aware rate limiting, and an optional Docker reproduction runner.

## What works in this prototype

- Android-first Flutter application.
- Incident Capsule state and evidence.
- Controlled real failure injection into the lab model.
- Camera evidence capture from the phone.
- Voice input from the phone.
- Evidence correlation and hypothesis state transitions.
- Adaptive-reproduction interface with Docker sandbox adapter.
- Verification gate before recovery.
- Explicit phone approval before recovery.
- Blue/Green lab environment.
- Prometheus metrics endpoint/configuration.
- Secondary security signal: endpoint-aware rate limiting and gateway telemetry.
- Structured workflow history and MTTR calculation.

## What is deliberately not faked

The prototype does not pretend that arbitrary production incidents can be solved. The lab uses a controlled, reproducible Green deployment regression so that the entire recovery loop can be tested repeatedly. The incident data is generated by the actual workflow and service state, not by a video or screenshot pretending to be a live system.

## Current boundary

The local-model integration is exposed as an architecture seam, while the prototype uses deterministic triage for the seeded failure. This is intentional: the team currently claims LLM proficiency C (experimented with local LLMs), not D. A real on-device model should be added and tested on the target iQOO device before claiming on-device deployment.

## Run backend

```bash
cd backend
npm install
npm start
```

Backend: http://localhost:8787

## Run lab

```bash
cd lab
docker compose up --build -d blue green gateway prometheus
```

- Blue: http://localhost:8081/health
- Green: http://localhost:8082/health
- Gateway: http://localhost:9090
- Prometheus: http://localhost:9091

Sandbox runner:

```bash
docker compose --profile tools run --rm reproducer
```

## Run Android

```bash
cd mobile
flutter pub get
flutter run
```

Android emulator uses `http://10.0.2.2:8787`. For a physical phone:

```bash
flutter run --dart-define=ONEOPS_API=http://<LAPTOP-LAN-IP>:8787
```

Allow the backend port through the laptop firewall on the local network.

## Prototype workflow

1. Start the lab.
2. Start the backend.
3. Start the Android app.
4. Tap **Inject failure**.
5. Optionally tap **Capture** and photograph the failure screen.
6. Tap **Investigate**.
7. Tap **Reproduce**.
8. Tap **Verify fix**.
9. Review the evidence and tap **Approve & recover**.
10. The Incident Capsule becomes **RECOVERED** and records MTTR.
